# Changelog

## v0.6.1 — 2026-10-26

Исправления по итогам игры вдвоём.

- **Инверсия движения исправлена**: обе оси левого стика переворачиваются
  (`invertMoveX/Y = true`). Проверено пользователем: вверх — вперёд, влево — влево.
- **Спринт**: игра мапит `ActionSprint` на **X** (`Gamepad_FaceButton_Left`). При удержании X
  мост пишет скорость 360 вместо 210. Проверено: второй Моно ускоряется.
- **Прыжок**: кнопка A у p2 не видна через `IsInputKeyDown`, добавлено чтение аналогового
  состояния кнопки (`GetInputAnalogKeyState`); прыжок только с земли, без двойного.
- Карта геймпадных действий игры теперь пишется в лог при старте моста
  (`ActionJump=A`, `ActionSprint=X`, `ActionCall=Y`, `EquipItem*=B`, `ActionCancelGrab=RT`).
- Убрана тяжёлая диагностика API (могла уронить игру); осталась только карта действий.
- Не сделано: **подбор предметов и интеракции**. `ActionCall` (Y) вызывается, но подбор
  предмета пока не подтверждён; двери/лифты/чекпоинты и враги — следующие задачи.

## v0.6 — 2026-10-26

Второй Моно управляется со второго геймпада: ходьба, камера, прыжок.

- Причина «пешка p2 стоит» найдена: `AddMovementInput` на p2 не даёт ускорения (даже с
  `bForce=true`), хотя `IsMoveInputIgnored()` возвращает `false`; сам пад 2 при этом
  читается через `GetInputAnalogKeyState`. Ввод игры для p2 не выполняется.
- Второй Моно ведётся через `UCharacterMovementComponent.Velocity` каждые 33 мс: работают
  коллизии, склоны, гравитация и анимация ходьбы. Скорость компенсирует торможение
  компонента между тиками моста.
- Камера p2 вращается правым стиком через `PlayerController:SetControlRotation` (yaw
  проверен по логу 160° → 303°, вид меняется).
- Прыжок: `Character::Jump()` игра для p2 игнорирует; принудительный
  `SetMovementMode(MOVE_Falling)` + вертикальная скорость дают нормальный прыжок. Только с
  земли: повторное A в воздухе не складывается в двойной прыжок.
- Постановка p2: ровно в точку p1, без свипа, с обнулением скорости и переводом в
  `MOVE_Walking`. Смещение в сторону убрано: свип упирается в камень и оставляет пешку
  зажатой, поэтому два Моно стоят в одной точке до первого движения p2.
- Капсула p2 игнорирует канал Pawn, иначе два Моно блокируют друг друга в одной точке.
  Побочный эффект: p2 проходит сквозь Шестую и врагов.
- Отладочный `bridge_test.txt` (значения стиков вместо пада) и `tools/test_bridge.ps1`:
  автоматическая проверка ходьбы/камеры/прыжка в `G:\LN2\test-install` без рук на паде.
  Реальный второй пад проверен в игре: в логе значения стика p2, за ними меняются
  позиция и скорость пешки.
- Проверено в изолированной копии: вперёд/назад/вбок, поворот камеры, прыжок; скриншоты
  `docs/img/v0.6-*.png`.

## v0.3 — 2026-10-26

Кооп работает: split screen, второй Моно.

- Найдена и устранена причина «все вызовы движка возвращают ноль»: UE4SS попадал на заглушку `xor eax,eax; ret` вместо `UObject::ProcessEvent`. `UE4SS.dll` пропатчен на настоящий `ProcessEvent` игры (`0x2875080`), ASLR-безопасно.
- `main.lua` v0.3: `bUseSplitscreen` на игровых уровнях, `CreatePlayer` для ControllerId 1, расстановка второго Моно рядом с первым, корректные пути конфига/лога (через `debug.getinfo`), отключение разделения в меню, лог в `LN2Coop.log`.
- `coop.cfg` — включение/выключение коопа без правки кода.
- `patch_ue4ss.ps1` — проверка SHA-256 игры и DLL, PE-маппинг RVA, бэкап `.orig`, идемпотентность.
- `UE4SS-settings.ini` под эту сборку (`HookInitGameState = 0` и др.).
- Мод установлен и проверен в игре пользователя: `local players 1 -> 2`, pawn `BP_PlayerPawn_C`, две камеры, экран разделён.
